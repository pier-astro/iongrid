# XSTAR products and conversion

The [XSTAR recipe](../examples/xstar-sim/README.md) varies `logxi`, `vturb` and `log_nh` while keeping density, input luminosity, source SED and any other XSTAR controls fixed in `settings.py`. Each point has its own working directory and recorded `xstar-params.json`. Independent points can run in local processes or HTCondor batches. The simulation scripts remain beside the outputs so a run can be reproduced or resumed later.

`packnpz` reads `xout_spect1.fits` and `xout_cont1.fits`. Their `XSTAR_SPECTRA` extensions provide the energy axis in eV and incident, transmitted and outward emission spectra. The `PARAMETERS` extension supplies `rlrad38`. The current recipe does not read `xout_lines1.fits`, `xout_rrc1.fits` or abundance products. It preserves XSTAR's native 9999-bin output when `ncn2=9999`; the actual grid is checked when packing.

The total optical depth is `-ln(transmitted / incident)` with zero incident bins treated as transparent and ratios clipped to the physical interval. Outward emission uses the predecessor XSTAR-to-XSPEC bin conversion: divide by `rlrad38`, scale to 10³⁸ erg s⁻¹ at 1 kpc, and convert energy flux to photons per energy bin using the local bin width. `xout_cont1.fits` supplies the continuum component; the line component is total minus continuum, with small negative differences from the two rounded files clipped while preserving the total. `emt_total` and `emt_lines` are exported by the example recipe. The XSTAR reference is 1 kpc, unlike the supplied CLOUDY recipe's 10 kpc; `REFDIST` and `REFLUM` retain this distinction in FITS and OGIP files.

The default source is XSTAR's power law (`spectrum=pow`). For a custom SED, place an XSTAR-format text spectrum in the run directory and set `SED_FILE = GRID_DIR / "sed.dat"` in `settings.py`. The old WINE workflow writes this format as a sample count followed by energy–flux pairs. The recipe copies it into every point and passes `spectrum=file`, `spectrum_file=sed.dat`, `spectun=0` to XSTAR. Keep the chosen SED beside the recipe. A changed SED or parameter set for a completed point requires a new run directory, preserving the provenance of existing products. Additional fixed XSTAR parameters can be set in `XSTAR_OPTIONS`; the three grid controls remain managed by the recipe.
