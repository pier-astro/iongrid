# Emission-table normalization

The additive tables contain bin-integrated photon flux at an engine-specific reference distance. Their XSPEC normalization multiplies that spectrum. Use the **1–1000 Ryd luminosity incident on the gas**, in erg/s, for the target source. A 2–10 keV or bolometric measurement needs conversion with the adopted incident SED. The luminosity seen by the gas may differ from the observer's estimate because of shielding, anisotropy, or variability.

The supplied CLOUDY and XSTAR tables already have the same physical output unit, photons cm$^{-2}$ s$^{-1}$ per bin, but they use different references. CLOUDY retains the simulated input luminosity and uses 10 kpc; the default recipe now keeps that luminosity fixed across nodes. The XSTAR exporter follows the historical `xstar2xspec` convention: it divides by the simulation luminosity and uses $10^{38}$ erg/s at 1 kpc. Matching the *unit* or reference distance does not make those luminosity conventions identical. Making them identical would require changing one engine's luminosity scaling, which is separate from a single fit normalization.

Let $D_L$ be the luminosity distance and $C_\Omega$ the global solid-angle covering fraction. Line-of-sight partial covering affects absorption separately. The scripts in each example folder are editable run records: set the variables at the top, then run `python calc-norm.py`. Set `REDSHIFT = None` and provide `DISTANCE_MPC` to use a measured luminosity distance. The script output is an initial normalization for the stated assumptions; handle cosmological redshifting of the spectrum separately, checking the fitting model's photon-flux convention.

## CLOUDY

The default deck specifies `luminosity {log_luminosity} range 1 to 1000 Ryd` and `hden {log_density} log`. The setup computes a separate inner radius for each `logxi` node:

$$r_0(\xi)=\sqrt{\frac{L_{\rm ion,sim}}{\xi n_H}}.$$

For the default $L_{\rm ion,sim}=10^{48}$ erg/s and $n_H=10^{10}$ cm$^{-3}$, `logxi=3` gives $r_0=10^{17.5}$ cm and `logxi=6.5` gives $r_0=10^{15.75}$ cm. This is an editable simulation reference chosen to keep the example geometrically thin, not an estimate of the target luminosity. The normalization for a target source is

$$\kappa_C=C_\Omega\left(\frac{10\,\mathrm{kpc}}{D_L}\right)^2\frac{L_{\rm ion,target}}{L_{\rm ion,sim}}.$$

This ratio assumes the same incident SED and a full-covering reference emission spectrum. Because the default simulation luminosity is common to all nodes, the same target luminosity, distance and global covering fraction imply one normalization across `logxi`. Tying the XSPEC normalizations also assumes that each component has the stated covering fraction; check how WINE applies geometry before counting it again. `iongrid` preserves the native luminosity of every CLOUDY run and does not rescale nodes after the simulation.

The varying radius requires checking the **smallest** radius at the highest `logxi`: at constant density, $\Delta r/r_0\simeq N_H/(n_Hr_0)$. The default upper grid corner, $N_H=10^{24}$ cm$^{-2}$ and `logxi=6.5`, gives $\Delta r/r_0\simeq0.018$. The one-number `radius` command sets only the inner radius; a second number would add an outer-radius or thickness stop, but the default deck instead stops at `stop column density`. The chosen radius limits the change in incident flux caused by geometric dilution across the slab. It does not prevent strong ionization stratification caused by internal attenuation at large columns. The relevant check is whether the ion fractions and transmitted ionizing continuum change enough across the slab to invalidate the intended single-ionization approximation; small or moderate changes may be acceptable for the application.

For a custom `xi` intensity deck, $L_{\rm ion,sim}(\xi)=\xi n_Hr_0^2$ may change from node to node, so a common physical covering fraction may require node-dependent normalizations. At the 10 kpc table reference the compiler applies one of two full-$4\pi$ conversions to each native emitted energy bin: $F_{\rm ref}=S(r_0/D_{\rm ref})^2$ when CLOUDY saved surface emission $S$, or $F_{\rm ref}=L/(4\pi D_{\rm ref}^2)$ when it saved integrated luminosity $L$. These are unit conversions. CLOUDY's separate `sphere` command controls closed-geometry radiative transfer; it is not selected by `xi` versus `luminosity`.

The compiler first reads the emission-unit heading in CLOUDY's `.out` log: intensity-case logs print `Intensity (erg/s/cm^2).`, while a tested luminosity-case run printed `Luminosity (erg/s) emitted by a shell with full coverage.`. If that heading is absent, the compiler falls back to `xi` or `luminosity` in the retained `.in` deck. For another brightness command, add `# iongrid emission input: intensity` or `# iongrid emission input: luminosity` to that deck after checking its native output units; ambiguous inputs raise an error. A `plane-parallel`/`spherical` switch would not identify these units. To represent a full-covering reference, do not specify a smaller covering factor inside CLOUDY as well; model geometric covering once downstream.

The supplied `abundances old solar 84` is an explicitly reproducible historical mixture. CLOUDY also supplies newer sets such as `GASS` (2010 solar), but no solar mixture is universally appropriate to every galaxy. A different mixture changes metal ionic columns, cooling, and the inferred $N_H$; it requires a new grid and comparisons against representative old-grid spectra and fits. Record the selected mixture in each copied deck, and choose compatible abundance references when comparing CLOUDY, XSTAR, and the fitting continuum. Do not silently reinterpret an existing `old solar 84` grid as a newer mixture.

In [the CLOUDY calculator](../examples/cloudy-sim/calc-norm.py), the default `CLOUDY_INPUT = "luminosity"` uses the grid-wide 1–1000 Ryd luminosity `L_ION_SIM_INPUT`; the `xi`-only variables can stay `None`. For a custom `xi` deck, set `CLOUDY_INPUT = "xi"` and supply `LOGXI`, `LOG_DENSITY`, and `RADIUS_CM` to reconstruct that node's implied luminosity. In both cases supply the target luminosity and distance. `COVERING_FRACTION = 1` gives the full-shell reference; use any WINE covering factor only once. The bundled $z=0.184$ and $10^{45}$ erg/s target values are **illustrative**, not measured PDS 456 inputs.

## XSTAR

The XSTAR recipe's `LUMINOSITY_38` becomes `rlrad38`; its input 1–1000 Ryd luminosity is $L_{\rm ion,sim}=10^{38}\,\texttt{rlrad38}$ erg/s. `iongrid.xstar` divides the outgoing spectrum by `rlrad38` and exports it at a reference luminosity of $10^{38}$ erg/s and a distance of 1 kpc. Consequently,

$$\kappa_X=C_\Omega\left(\frac{1\,\mathrm{kpc}}{D_L}\right)^2\frac{L_{\rm ion,target}}{10^{38}\,\mathrm{erg\,s^{-1}}}.$$

Set `L_ION_SIM` in [the XSTAR calculator](../examples/xstar-sim/calc-norm.py) to the actual input value as a run record. It does not appear in the final expression because the table conversion already removed it. The supplied XSTAR recipe keeps that input fixed across its `logxi` grid.

## Fitting emission and absorption together

In the optically thin limit, at fixed ionization and SED, emitted line power often scales approximately as $C_\Omega L_{\rm ion}N_H$, and unsaturated absorption optical depth scales approximately as $N_H$ times the relevant ionic fraction. A factor-of-two error in the emission scalar **might** be partly absorbed by $N_H$ if absorption is weakly constrained. It will generally change the predicted absorption and can change line ratios, thermal state, and escape probabilities; saturated lines behave differently. There is no general factor-of-two-to-four tolerance. Tying emission and absorption $N_H$ tests the hypothesis that they sample the same gas, while a free emission scalar measures the combination of covering, incident luminosity, and model mismatches. For WINE, compare fits with a physically motivated range for the scalar and with a fully free scalar; inspect joint constraints and residuals before assigning a physical interpretation. The default CLOUDY recipe has a common input luminosity, so that range need not change solely because `logxi` varies. Count WINE's geometric covering once: if it already multiplies the emission, leave `COVERING_FRACTION = 1` in these scripts.

The [CLOUDY HAZY C24 manual](https://data.nublado.org/workshop/24Tokyo/hazy1_Tokyo24.pdf) defines `xi`, shell geometry, and available abundance sets. The XSTAR manual describes its [input luminosity](https://heasarc.gsfc.nasa.gov/docs/software/xstar/docs/sphinx/xstardoc/docs/build/html/xstarinput.html) and [table normalization](https://heasarc.gsfc.nasa.gov/docs/software/xstar/docs/sphinx/xstardoc/docs/build/html/xstar2xspec.html).
